# 01 - Onboarding avatar pipeline (Persona + selfie-to-avatar)

Research date: 2026-09-11 (day 1 of HackRice 2026).
Scope: the player takes a selfie at game start, it passes through Persona, and the player gets a game avatar that looks like them inside the PixiJS isometric city.

Setup follow-up (2026-09-11): the step-by-step Persona integration, keys, webhook signing, and every other API are in [../SETUP.md](../SETUP.md).
It confirmed that the npm package is `persona` (v5.8.0), templates are still `itmpl_`, `environmentId` replaces the deprecated `environment: 'sandbox'`, and the API version is `2025-12-08`.
It also found that the age check returns as a pass or fail check (`selfie_age_comparison`), not an age number, and that the HackRice Persona challenge is "Prove You're Human" ("access depends on a verified human").
Because sandbox performs no real verification, ask the Persona booth for a production environment.

## TL;DR

- Persona gives us a drop-in Web SDK (`npm i persona`) that runs a hosted Inquiry with selfie liveness, selfie age estimation, and optional government ID, and it is free in Sandbox.
- **Catch:** Sandbox performs no real verification and shows sample data, with a force-pass or force-fail toggle ([Environments](https://docs.withpersona.com/environments)).
  That means we should not count on getting the player's real selfie back from Persona during the demo.
  We capture our own avatar photo with `getUserMedia` on our consent screen and use Persona as the "real human, 18+" gate.
- Ready Player Me is dead for third parties: Netflix acquired it and shut down the public platform and developer APIs on 2026-01-31 ([Variety](https://variety.com/2025/digital/news/netflix-acquires-ready-player-me-games-avatar-creation-1236612915/), [Avatar SDK blog](https://avatarsdk.com/blog/2026/01/15/switch-from-ready-player-me-to-avatar-sdk-fast-familiar-production-ready/)).
- Best avatar path for 24h: a **2D chibi sprite sheet generated by Gemini 3.1 Flash Image (Nano Banana 2)** from the selfie plus a style reference, sliced into 4 or 8 directional frames, and loaded as Pixi textures.
  It costs about $0.07 an image and takes roughly 10-20 s.
- 3D (Meshy image-to-3D, then pre-rendering 8 directions with three.js) is a stretch goal that adds 1-3 min of latency per player.
- Fallback: a parametric avatar built from pre-made parts, where the player picks skin, hair, and outfit in about 5 seconds, so the demo never blocks on an API.

## 1. Persona

### What the product offers

- **Inquiry** is Persona's unit of a verification session, built from an **Inquiry Template** (`itmpl_...`) you configure in the dashboard with steps like selfie, government ID, and database checks ([What are Inquiries](https://help.withpersona.com/articles/2BerKqpgNIRG81jX0goCMU/)).
- Integration methods ([Choosing an integration method](https://docs.withpersona.com/choosing-an-integration-method)):
  - **Hosted flow:** redirect to a Persona-hosted URL, which takes zero code.
  - **Embedded flow (Web SDK):** a modal or iframe on our page, with a few lines of JS ([Embedded Flow Overview](https://docs.withpersona.com/embedded-flow)).
  - Native iOS and Android SDKs and a raw API also exist, but we do not need them.
- **Selfie verification** covers face image quality, face comparison against an ID photo, liveness (anti-spoof and presentation attacks), and age estimation ([Selfie Verifications API](https://docs.withpersona.com/api-reference/verifications/selfie-verifications)).
  Capture can be a single front-facing portrait or a three-angle capture (left, center, right).
  Checks include `selfie_liveness_detection`, `selfie_pose_detection`, `selfie_glare_detection`, and `selfie_age_threshold_comparison`.
- **Selfie Age Estimation** is a selfie-only 18+ check with no ID required.
  It returns an estimated age, an image-quality score, and a spoof likelihood, and it escalates to Government ID when the estimate lands near the threshold ([Selfie Age Estimation help](https://help.withpersona.com/articles/45UrKCZtpwW5Z7DJ0JW0vM/), [product page](https://withpersona.com/product/verifications/selfie-age-estimation)).
  It is certified by the Age Check Certification Scheme ([PR Newswire](https://www.prnewswire.com/news-releases/persona-selfie-age-estimation-certified-by-the-age-check-certification-scheme-302310071.html)).
- **Government ID verification** is available as a separate verification type ([Retrieve a Government ID Verification](https://docs.withpersona.com/api-reference/verifications/government-id-verifications/retrieve-a-government-id-verification)).
- **Accounts and reverification:** Persona Accounts let you link inquiries to one person and compare new selfies against earlier ones ([Accounts help](https://help.withpersona.com/articles/3Yo5qPfWb5mGm3FGh0bWKH/), [Reverify blog](https://withpersona.com/blog/reverify/)).
  Persona also sells Selfie Recognition (face deduplication), which supports a "one avatar per human" claim, but its page returned 403 to us and it is likely not in the free sandbox.

### Quick web integration

From the [Embedded Flow quickstart](https://docs.withpersona.com/quickstart-embedded-flow):

```ts
import Persona from "persona";

const client = new Persona.Client({
  templateId: "itmpl_...",      // from dashboard, e.g. a Selfie + Age Estimation template
  environmentId: "env_...",     // sandbox environment id
  referenceId: playerSessionId, // our id for this player
  onReady: () => client.open(),
  onComplete: ({ inquiryId, status, fields }) => {
    // send inquiryId to our backend; backend confirms status via API/webhook
  },
});
```

- Client callbacks are only for UI coordination, and Persona says to use webhooks or the API for anything that depends on the inquiry's state ([Client Callbacks](https://docs.withpersona.com/embedded-flow-client-callbacks)).
  For a hackathon, the backend can call `GET /api/v1/inquiries/{id}` once `onComplete` fires, and then it trusts `status`.
- Setup time: sign up, toggle Sandbox, pick or clone a Selfie template, copy `templateId` and `environmentId`, and paste the snippet.
  This takes about 30-60 min end to end.

### Getting the selfie image back

- Yes, via API.
  `GET https://api.withpersona.com/api/v1/verification/selfies/{verification-id}` returns `center-photo-url`, `left-photo-url`, `right-photo-url`, `video-url`, and `photo-urls[]` ([Retrieve a Selfie Verification](https://docs.withpersona.com/api-reference/verifications/selfie-verifications/retrieve-a-selfie-verification.md)).
- File URLs look like `https://files.withpersona.com/...?access_token=...`, signed so that they load without an API key ([Downloading Files](https://docs.withpersona.com/downloading-files)).
  Treat them as secrets and never put them in client logs.
- **Sandbox caveat:** "Real verifications are not performed within sandbox mode" and "sample data will be shown", and names are overwritten to "Alexander J Sample" ([Environments](https://docs.withpersona.com/environments), [Sandbox vs Production](https://support.withpersona.com/hc/en-us/articles/1500003167262-Sandbox-vs-Production-Environments)).
  We could not confirm whether sandbox keeps the actual camera frame or swaps in a sample image.
  **Verify this in the first hour.**
  If sandbox returns the real frame, we can feed `center-photo-url` straight into avatar generation, which is the cleanest story for the judges.
- Production access requires approval and a paid plan ([Persona API quickstart](https://docs.withpersona.com/api-quickstart-tutorial), [Sandbox vs Production](https://support.withpersona.com/hc/en-us/articles/1500003167262-Sandbox-vs-Production-Environments)).
  Ask the Persona sponsor booth whether they give hackathon teams production or demo credits.

### Sandbox and free access

- A free signup includes Sandbox and an API key right away, and Sandbox inquiries cost nothing ([Environments](https://docs.withpersona.com/environments), [API Keys](https://docs.withpersona.com/api-keys)).
- Sandbox has a force-pass or force-fail toggle, so we can demo both the "verified" and the "rejected, under 18" branches deterministically.

### Consent, privacy, and PII handling on the Persona side

- Persona shows its own consent and disclosure screens inside the flow.
  We should still show our own short notice before opening it (see section 4).
- **Redaction API:** `Redact an Inquiry` permanently deletes PII for the inquiry and all child verifications, and it runs asynchronously ([Redact an Inquiry](https://docs.withpersona.com/api-reference/inquiries/redact-an-inquiry), [Redact a Verification](https://docs.withpersona.com/api-reference/verifications/redact-a-verification)).
  Persona keeps data indefinitely until the customer deletes it, or it can set an automatic retention period ([redaction help](https://help.withpersona.com/articles/42ubXB5lJPWNaITI0uJfrI/), [Security and Privacy](https://help.withpersona.com/articles/4SxXLtuLwYAWSkxWbHQtoo/)).
- Plan: call Redact on the inquiry as soon as the avatar is generated, and say so on stage.

### What a Persona sponsor judge wants to see

- A verification that matters to the product, not just a login screen:
  - **Liveness** so that "you are a real person, and this avatar is you": no uploading a celebrity photo, and the city is populated by verified humans.
  - **18+ age estimation** because the game simulates adult finance (credit cards, 401k, loans), and minors get a gated "learning mode" instead.
  - **One avatar per human**, via referenceId and Accounts, so each person gets one leaderboard entry.
- A visible decision branch driven by Persona's result (for example, a pass unlocks full mode and a fail or under-18 result unlocks restricted mode).
- Privacy-by-design, such as redacting the inquiry right after use and showing the redaction call in the demo.
- Webhook or API confirmation on the server rather than trusting the client callback.

## 2. Selfie-to-avatar options, ranked for 24h

| Rank | Option | Latency | Cost per avatar | Output | Likeness and consistency | 24h risk |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 2D sprite via Gemini 3.1 Flash Image | ~10-20 s per image | ~$0.067 (1K) | PNG sheet, sliced | Good likeness; direction-to-direction consistency is fair and improves with a single-sheet prompt | Low |
| 2 | 2D sprite via OpenAI gpt-image-2 | ~20-60 s | ~$0.05 (medium) - $0.21 (high) | PNG | Good; strong prompt adherence | Low |
| 3 | Parametric parts avatar | instant | $0 | Pixi container of layered parts | Weak likeness, perfect consistency | Very low |
| 4 | Image-to-3D (Meshy / Tripo / Hunyuan3D / Rodin) + prerender | 1-4 min | $0.16-$0.43 | GLB | Stylized likeness; any angle is consistent once built | Medium-high |
| 5 | Avatar SDKs (Avaturn, Avatar SDK) | 30 s - minutes | $800/mo plan for the API | GLB | Realistic, but clashes with the chibi art | High (cost and time) |
| x | Ready Player Me | n/a | n/a | n/a | n/a | Dead since 2026-01-31 |

### (a) 2D stylized sprite via image models (recommended)

- **Gemini:** current model IDs are `gemini-3.1-flash-image` (Nano Banana 2), `gemini-3.1-flash-lite-image` (Lite, fastest), and `gemini-3-pro-image` (Pro), with `gemini-2.5-flash-image` as legacy ([Gemini image generation docs](https://ai.google.dev/gemini-api/docs/image-generation), [model page](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-image)).
  - Up to 14 reference images, including up to 4 "character consistency" images and 3 style references on Flash.
    This is exactly what we need: the selfie as the character reference, and one of our tile-pack sprites as the style reference.
  - Aspect ratios include 1:1, 3:2, 4:3, 16:9, and 21:9, so we can put a 4-direction turnaround in one wide 21:9 or 16:9 image.
  - Pricing: about $0.067 for Nano Banana 2 at 1K, about $0.034 for Lite, and about $0.134 for Pro ([myarchitectai pricing roundup](https://www.myarchitectai.com/blog/nano-banana-api-pricing), [IntuitionLabs](https://intuitionlabs.ai/articles/ai-image-generation-pricing-google-openai)).
  - All outputs carry an invisible SynthID watermark, which is a nice responsible-AI talking point.
  - Transparent background is not documented, so prompt for a flat solid chroma color (for example `#FF00FF`) and key it out client-side.
- **OpenAI gpt-image-2:** supports reference-guided editing with up to 16 images.
  It is token-priced, which works out to roughly $0.006 (low), $0.053 (medium), or $0.211 (high) per 1024x1024 ([costgoat](https://costgoat.com/pricing/openai-images), [WaveSpeed](https://wavespeed.ai/blog/posts/gpt-image-2-pricing-2026/)).
  It is the hot-swap backup if Gemini rate-limits us.
- **Consistency technique:**
  1. Generate **one** image containing all directions side by side (front, 3/4 front, side, back), rather than separate calls.
     This keeps clothing and colors consistent.
  2. Fix the canvas layout in the prompt ("4 equal columns, character centered in each, feet on the same baseline, full body, isometric 3/4 top-down camera like the reference").
  3. Slice by fixed column width, chroma-key the background, trim, and set the anchor at the feet.
  4. Mirror the frames horizontally to get 8 directions from 5.
  5. For walking, either generate a second sheet with 2 step poses or fake it with a 2-frame bob and squash tween in Pixi.
     A bob tween is fine for a city sim.
- Latency: a single call of about 10-20 s fits well behind the Persona flow and a short "building your citizen..." animation.

### (b) Image-to-3D (stretch goal)

- **Meshy:** `POST /openapi/v1/image-to-3d` takes a URL or base64 data URI and supports `pose_mode: "a-pose"`, `ai_model: meshy-6 | meshy-7`, and `model_type: lowpoly`.
  Output formats are GLB, FBX, OBJ, and USDZ, and the API has rigging and animation endpoints ([Meshy Image to 3D API](https://docs.meshy.ai/en/api/image-to-3d)).
  - Cost is 20 credits untextured or 30 textured on Meshy 7, and a full character with remesh, rig, and animation is about 43 credits.
    API credits are prepaid ([aitrendtool](https://aitrendtool.com/tools/meshy), [Meshy API](https://www.meshy.ai/api)).
  - Latency: a preview mesh in about 30 s, texturing in 1-6 min depending on queue ([Meshy API quickstart](https://www.meshy.ai/tutorials/api-quickstart-image-to-3d)).
- **Tripo:** 1 credit = $0.01; P1 image-to-3D costs $0.28 untextured or $0.35 textured, and requests are async ([Tripo Developers](https://developers.tripo3d.ai/en), [Tripo pricing guide](https://lorphic.com/tripo-ai-pricing-explained-guide/)).
- **Hunyuan3D on fal.ai:** $0.16 (v2) to about $0.25 (v3) per run, which is the cheapest option with no subscription ([fal Hunyuan 3D Rapid](https://fal.ai/models/fal-ai/hunyuan-3d/v3.1/rapid/image-to-3d), [costgoat Hunyuan](https://costgoat.com/pricing/hunyuan-3d)).
- **Hyper3D Rodin:** $0.40 per generation on fal, and the standalone API needs a $120/mo business plan ([fal Rodin](https://fal.ai/models/fal-ai/hyper3d/rodin), [3DAI Studio comparison](https://www.3daistudio.com/blog/best-3d-model-generation-apis-2026)).
- Key trick: do **not** feed the raw selfie to image-to-3D, because faces come out uncanny.
  Feed the **front-view chibi image from step (a)**, since image-to-3D models handle clean, stylized, full-body, A-pose inputs far better.
- Verdict: good wow factor ("rotate your 3D self"), but it adds minutes of latency per player and has more failure modes.
  Only do it if one person is dedicated to it after the MVP loop works.

### (c) Avatar SDKs

- **Ready Player Me:** acquired by Netflix, and the public creator, PlayerZero, and developer APIs were shut down on 2026-01-31 ([Variety](https://variety.com/2025/digital/news/netflix-acquires-ready-player-me-games-avatar-creation-1236612915/), [Ryan Schultz](https://ryanschultz.com/2025/12/22/metaverse-bombshell-netflix-acquires-ready-player-me-what-does-this-mean-for-metaverse-platforms-using-ready-player-me-avatars/), [Genies alternatives](https://genies.com/blog/ready-player-me-discontinued-alternatives)).
  Do not use it.
- **Avaturn:** selfie to realistic 3D avatar, with the API and SDK gated behind a **$800/month** Pro plan ([Avaturn pricing](https://avaturn.me/pricing/)).
  Its realistic style also clashes with a LEGO-like chibi city.
  Not worth it.
- **Avatar SDK (itseez3d):** positions itself as the RPM migration target ([migration guide](https://avatarsdk.com/blog/2026/07/07/ready-player-me-migration-guide/)).
  It is a sales-driven enterprise product, so it is unlikely to be self-serve within hours.

### (d) Parametric / procedural avatar (fallback)

- Pre-draw about 4 skin tones, 6 hair styles, 4 hair colors, 4 tops, and optional glasses as layered sprites per direction, and tint layers with Pixi `tint` so we need fewer assets.
- Attribute detection: either let the player pick (fastest and most reliable), or send the selfie to Gemini text with a JSON schema (`{skinTone, hairStyle, hairColor, glasses, facialHair}`) and auto-select parts.
  That call takes about 2 s and costs fractions of a cent.
- Zero latency, zero risk, and perfectly consistent with the art pack.
  This is our demo-day safety net and also the NPC generator for the other ~50 citizens.

## 3. Showing a 3D avatar inside PixiJS 2D

| Option | Notes | Verdict |
| --- | --- | --- |
| Pre-render GLB to 8-direction sprite frames with three.js offscreen, then Pixi textures | One-time cost of about 1 s per avatar in the browser; after that it is just sprites, so it matches the isometric 2D look, is cheap at 50+ citizens, and needs no depth-sorting headaches | **Recommended** |
| three.js and Pixi on one WebGL context | Officially supported in v8: `pixiRenderer.init({ context: threeRenderer.getContext(), clearBeforeRender: false })` plus `resetState()` between renders ([PixiJS guide](https://pixijs.com/8.x/guides/third-party/mixing-three-and-pixi)); textures are not shared, and correct isometric depth ordering between a 3D layer and 2D buildings is painful | Only for a special "inspect your avatar" view |
| pixi3d | Supports PixiJS v5-v7 only, with no v8 support; the last npm publish was 2.5.0 in Dec 2023 ([GitHub](https://github.com/jnsmalm/pixi3d), [npm](https://www.npmjs.com/package/pixi3d)) | Avoid |
| Separate three.js canvas overlaid on Pixi | Easy, but the avatar cannot go behind buildings | Avoid for the map; fine for a profile card |

Pre-render recipe:

1. Load the GLB with `GLTFLoader` into an offscreen `WebGLRenderer({ alpha: true, preserveDrawingBuffer: true })` at 256x256.
2. Use an `OrthographicCamera` at the isometric angle (about 30 deg elevation, matching the tile art), with flat lighting and optionally a toon material for the chibi look.
3. Rotate the model through 8 yaw angles (and optionally step through a few walk-animation keyframes from Meshy's rig), rendering each to a canvas cell of an atlas.
4. `Texture.from(atlasCanvas)` in Pixi, cut into frames, then `AnimatedSprite` per direction.

This makes the 2D and 3D paths converge: both produce the same 8-direction frame atlas, so the game code does not care where the avatar came from.

## 4. Privacy and ethics

- **Texas CUBI** (Tex. Bus. & Com. Code 503.001) applies to us in Houston.
  Capturing a "record of hand or face geometry" for a commercial purpose requires notice and consent **before** capture.
  It bans selling or disclosing the data, requires reasonable care, and requires destruction within a reasonable time, no later than 1 year after the purpose expires.
  Only the Texas AG can enforce it, and there is no private right of action ([Texas AG](https://www.texasattorneygeneral.gov/consumer-protection/file-consumer-complaint/consumer-privacy-rights/biometric-identifier-act), [ZwillGen](https://www.zwillgen.com/privacy/texas-cubi-law-and-biometric-privacy/)).
  The AG has used it aggressively, winning $1.4B from Meta in 2024 ([Bracewell](https://www.bracewell.com/resources/billion-dollar-liability-understanding-your-obligations-under-the-texas-capture-or-use-of-biometric-identifier-act/)).
- **Illinois BIPA** is the strictest law: it requires a written release (e-signature is OK since the 2024 amendment), a published retention and destruction policy, and it has a private right of action.
  The 2024 amendment limited damages to one recovery per person rather than per scan ([Davis Wright Tremaine](https://www.dwt.com/blogs/privacy--security-law-blog/2024/08/illinois-bipa-biometrics-law-amended-for-damages), [King & Spalding](https://www.kslaw.com/news-and-insights/illinois-bipa-reform-takes-effect)).
- A photo by itself is arguably not a "biometric identifier" under either law, but face geometry computed by Persona is.
  Persona acts as our processor, so the notice and consent obligations sit with us.
- **Minimal-retention approach for the demo:**
  1. Show a one-screen consent before the camera opens: "We take one photo to (1) confirm you are a real adult via Persona and (2) draw your cartoon avatar. We delete the photo right after. [I agree] [Skip - pick an avatar instead]".
     Always offer the skip path.
  2. Keep our own captured frame only in browser memory as a Blob, send it once to the image API, and never write it to disk or the DB.
  3. Store only the **generated cartoon sprite** (not biometric) and Persona's `inquiryId` and `status`.
  4. Call Persona **Redact Inquiry** right after we read the result.
  5. Know the model providers' retention: the Gemini paid tier does not train on data, but the free tier may, so use a billed key.
  6. Run no face embeddings or face matching of our own, and leave all biometric processing to Persona.
- Ethics talking points: cartoonization avoids deepfake-grade likeness, SynthID marks generated images, and the skip path means verification is not coerced.

## RECOMMENDED PIPELINE

1. **Consent screen** (DOM overlay): short CUBI-style notice, "I agree" or "Skip".
   Skip goes straight to step 6b.
2. **Capture:** our own `getUserMedia` modal grabs one 1024px front-facing JPEG into memory.
   We capture it ourselves because Sandbox may not return the real selfie.
3. **Persona Embedded Flow** (sandbox, `npm i persona`) with a template of Selfie liveness plus Selfie Age Estimation (18+) and `referenceId = sessionId`.
   On `onComplete`, the backend calls `GET /api/v1/inquiries/{id}` and reads `status` and the age check.
   - Approved and 18+ unlocks full mode (credit, loans, investing).
   - Declined or under 18 unlocks "Learning mode", or retry.
   - Stretch: if real selfie URLs come back, use `center-photo-url` as the avatar source and drop step 2.
4. **Avatar generation** (backend, in parallel with step 3 so latency hides behind the Persona UI): call `gemini-3.1-flash-image` with the selfie as the character reference and one art-pack sprite as the style reference.
   The prompt asks for a "4-column turnaround sheet, chibi isometric citizen, flat #FF00FF background".
   Timeout is 25 s, with one retry.
5. **Post-process** (client): slice the columns, chroma-key, trim, set the foot anchor, and mirror to 8 directions.
   Build a Pixi `Spritesheet` and `AnimatedSprite`, and add a bob tween for walking.
6. **Fallbacks, in order:**
   - (a) Gemini error or timeout: retry once with `gpt-image-2` and the same prompt.
   - (b) Still failing, or the user skipped: the parametric avatar creator, optionally auto-filled by a Gemini JSON attribute call.
   - (c) Offline or no-Wi-Fi demo: 3 pre-generated team-member avatars cached in `/public`, plus Persona's sandbox force-pass toggle.
7. **Cleanup:** drop the selfie Blob, call Persona Redact Inquiry, and persist only the sprite PNG with `inquiryId` and status.
8. **Stretch (3D):** send the generated front-view chibi image to Meshy image-to-3D (`a-pose`, `lowpoly`, then rig), pre-render 8 directions with three.js offscreen into the same atlas format, and add a "view your 3D self" profile card using the shared-context approach.
